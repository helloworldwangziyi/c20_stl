# 第 10 章：配套练习任务书

这些练习按项目教学约定只给目标、契约和验收标准，不直接提供完整实现。每题都先自行
完成，再用标准库行为、编译器警告和测试验证。

## 1. 练习一：lifetime_probe 生命周期计数器

### 目标

用一个类型观察默认构造、拷贝、移动和析构，建立对象生命周期的直观认识。它也会成为
后续内存工具和容器测试的公共工具。

### 接口契约

实现 `lifetime_probe`，提供：

- 默认构造、拷贝构造、拷贝赋值、移动构造、移动赋值、析构。
- 分别统计六种操作次数的静态计数器。
- 当前存活对象数量 `alive`。
- 重置计数器的静态函数；重置时由测试保证没有旧对象干扰。

移动操作不抛异常。每次完整构造增加 `alive`，每次析构减少 `alive`，赋值不改变对象数量。

### 注意点

- 拷贝构造和移动构造也是构造，不能只统计默认构造。
- 区分“累计操作次数”和“当前存活数量”。
- 测试中的临时对象也会影响计数，先把预期逐行写出来。

### 验收清单

- 默认构造一个对象后，默认构造次数和 `alive` 都符合预期。
- 分别触发一次拷贝构造、拷贝赋值、移动构造、移动赋值。
- 自拷贝赋值、自移动赋值不破坏对象。
- 离开作用域后，析构次数增加，`alive` 相应减少。
- 所有测试通过，且测试结束没有仍存活的测试对象。

## 2. 练习二：shape 多态体系

### 目标

练习抽象接口、虚函数覆盖、基类引用、智能指针和虚析构。

### 接口契约

实现：

- 抽象基类 `shape`：公开虚析构，只读面积接口 `area()`。
- `rectangle`：保存宽和高，构造时拒绝非正尺寸。
- `circle`：保存半径，构造时拒绝非正半径。
- `double twice_area(const shape&)`：只依赖基类接口。

派生类覆盖函数必须写 `override`，类或函数是否需要 `final` 由设计说明理由。

### 注意点

- 不要把 `shape` 按值作为多态对象容器元素。
- `unique_ptr<shape>` 删除派生对象时，虚析构不可缺少。
- 浮点面积比较不要机械要求所有计算都逐位相等。

### 验收清单

- `static_assert(std::is_abstract_v<shape>)` 成立。
- `rectangle{2, 3}.area()` 为 6，圆形面积符合所选精度。
- 通过 `shape&` 调用时执行派生类实现。
- 通过 `unique_ptr<shape>` 创建、使用并销毁两种图形。
- 非法尺寸在构造时被拒绝，全部测试通过。

## 3. 练习三：RAII 文件包装类

### 目标

用对象生命周期管理 `std::FILE*`，确保每个成功打开的文件恰好关闭一次。

### 接口契约

实现 `raii_file`：

- 构造函数接收路径和模式，打开失败时抛出异常。
- 析构时关闭仍然持有的文件。
- 禁止拷贝构造和拷贝赋值。
- 提供 `get()` 访问句柄，但不转移所有权。
- 可选进阶：实现不抛异常的移动构造和移动赋值，转移后来源对象为空。

### 注意点

- 两个对象不能误以为各自拥有同一个句柄。
- 移动赋值若已持有文件，要先正确处理旧资源。
- 不要在 `get()` 后让外部随意 `fclose`，否则所有权规则会被破坏。

### 验收清单

- 创建临时文件，通过包装类读取并验证内容。
- 正常返回、提前返回、异常离开三种路径都不会泄漏文件。
- 拷贝操作在编译期不可用。
- 若实现移动，移动后来源句柄为空，最终只关闭一次。
- 使用编译器警告和可用的运行检查工具验证，无额外仓库产物。

## 4. 练习四：简化版 unique_ptr

### 目标

理解独占所有权、禁止拷贝、移动转移和 RAII。只管理单个对象，不处理数组和自定义删除器。

### 接口契约

实现类模板 `mini_unique_ptr<T>`：

- 可从空指针或裸指针构造，析构释放仍持有的对象。
- 禁止拷贝，支持 `noexcept` 移动。
- 提供 `get()`、`release()`、`reset()`。
- 提供 `operator*`、`operator->`、`explicit operator bool()`。
- 移动后来源为空，目标取得唯一所有权。

### 注意点

- `release()` 是主动交出所有权，之后由调用者负责释放。
- `reset()` 接收新指针时，要处理旧对象。
- 自移动赋值不能导致误删后仍保存悬垂指针。
- 解引用空指针属于错误使用，不需要为它定义“安全返回值”。

### 验收清单

- 用带析构计数的对象验证恰好释放一次。
- 编译期验证不可拷贝、可以移动。
- 验证 `get`、解引用、箭头访问和布尔转换。
- 验证 `release` 后不再自动释放，并由测试手动回收。
- 验证 `reset`、空指针、自移动赋值和嵌套作用域。

## 5. 练习五：vector 的特殊成员函数

### 目标

在已有 vector 基本实现上补齐析构、拷贝和移动，使值语义与标准容器一致。此题应在基础
元素操作和容量管理完成后再做。

### 接口契约

- 析构所有已构造元素，再释放原始存储。
- 拷贝构造得到内容相同、存储独立的副本。
- 拷贝赋值处理自赋值，并给出明确的异常安全保证。
- 移动构造和移动赋值转移存储，来源保持有效且可析构。
- 不抛异常的移动操作标为 `noexcept`。

### 注意点

- 容量、大小和指针必须作为同一组状态维护。
- 非平凡类型不能只复制字节，元素需要逐个构造和析构。
- 扩容时是否移动元素与元素移动构造是否 `noexcept` 有关。
- 拷贝赋值中途抛异常时，不能泄露存储或破坏对象基本不变量。

### 验收清单

- 用 `lifetime_probe` 验证没有漏析构、重复析构和泄漏。
- 修改副本不影响原 vector。
- 自拷贝赋值、自移动赋值后对象仍有效。
- 移动后来源可安全析构、重新赋值和继续按约定使用。
- 与 `std::vector` 对照大小和内容，`ctest` 全绿。

## 6. 练习六：list 迭代器类

### 目标

把节点指针封装成真正的双向迭代器，理解迭代器公开操作与容器内部结构的关系。

### 接口契约

迭代器至少支持：

- `operator*` 和 `operator->` 访问元素。
- 前置、后置 `operator++`。
- 前置、后置 `operator--`。
- 同类型迭代器的相等与不等比较。
- 默认构造，以及从容器节点构造的内部路径。

可选进阶：增加 const 迭代器及普通迭代器到 const 迭代器的转换。

### 注意点

- `end()` 是哨兵位置，不能解引用。
- 前置递增通常返回新位置的引用，后置递增返回旧位置的副本。
- 不要暴露节点所有权；迭代器只观察容器，不负责删除节点。
- 容器失效规则决定迭代器何时失效，不能仅凭指针非空判断有效性。

### 验收清单

- 正向遍历与 `std::list` 的元素顺序一致。
- 从末尾按合法范围反向遍历，顺序正确。
- 前置与后置递增、递减的返回值符合迭代器语义。
- `operator->` 能访问元素类型的成员。
- 空容器满足 `begin() == end()`，全部测试通过。
